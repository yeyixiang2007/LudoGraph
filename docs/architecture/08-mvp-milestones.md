# MVP 里程碑与验收标准

- **状态：** v1 设计草案。
- **MVP 定义：** 能对单游戏、单子系统的公开 fixture 完成“抽取 → 证据校验 → 断言导入 → 可追溯查询 → 三类有界验证 → 版本 diff”，并在语义不确定时拒绝过度承诺。
- **出口原则：** 每个阶段的交付物必须可运行或可检查；没有真实验证证据的目标不得标记完成。

## 1. 阶段总览

```text
M0 合同冻结 → M1 本体/合同 → M2 抽取 → M3 图谱 →
M4 查询 → M5 验证快筛 → M6 SMT 精化 → M7 版本/系统验收
```

阶段可并行开发，但里程碑出口依赖项未满足时不得进入下一阶段的集成验收。

## 2. M0：范围和合同冻结

### 交付物

- 本需求、模块、架构和图谱模式草案；
- 统一接口草案和结果协议；
- 17 标签、24 谓词计数裁决记录；
- 公开、可归因 fixture 目录规范；
- ADR 目录和开放问题清单。

### 出口条件

- 所有跨模块字段有唯一归属；
- `unknown`/`not-modeled`/`bounded-no-counterexample` 语义已写入接口；
- 不存在“25 个关系但无第 25 项定义”的隐式实现；
- 评审者可以从需求追溯到至少一个验收项。

## 3. M1：合同与本体校验

### 交付物

- 版本化 JSON Schema；
- 17 个叶子标签和 24 个谓词白名单；
- domain/range 矩阵；
- qualifiers、certainty、evidence、uncovered、错误码枚举；
- 确定性 Assertion ID 规范；
- 合法/非法 JSON fixture。

### 出口条件

- 合法 fixture 全部通过；
- 标签、谓词、domain/range、证据、限定值的非法 fixture 全部被拒绝；
- quote 连续性检查为硬门槛；
- 同一输入的 Assertion ID 重跑稳定；不同来源不会只因三元组相同而合并。

## 4. M2：本体受限抽取

### 交付物

- chunk 来源登记和确定性切分；
- proposer 抽象接口；
- validator 与 uncovered 分类；
- gold set 最小版本；
- 抽取层指标报告。

### 出口条件

- 无模型 fixture 能通过确定性 proposer 跑通合同；
- 每个节点、claim、uncovered 项都有 span；
- 语义无法表示的文本确实进入 uncovered 而不是被丢弃；
- 抽取报告分别给出 precision/recall、拒绝指标、domain/range 违规率、证据覆盖率；
- 目标：证据边界检查 100%，domain/range 违规率 0（若未达成必须阻断 MVP，不得降级宣称）。

## 5. M3：断言存储与图谱导入

### 交付物

- Assertion 规范存储 adapter；
- 关系属性/独立 Assertion 两种投影；
- 幂等导入、冲突并存、supersedes；
- provenance 查询；
- 索引/约束迁移脚本。

### 出口条件

- 同一 envelope 重试不重复写入；
- 修订不覆盖历史，旧断言仍可审计；
- 两种投影对约定查询给出语义等价结果；
- 任一返回事实能回到 source/chunk/span；
- 后端替换不改变抽取合同。

## 6. M4：查询路由

### 交付物

- Intent IR 和槽位枚举；
- 快速模板路径；
- 一个后端能力矩阵；
- schema-aware 方言编译器；
- 查询拒绝与 provenance 输出。

### 出口条件

- 合法问题生成参数化查询；
- schema 外问题被拒绝或明确不可回答；
- 后端不支持特性时返回能力错误而非不可执行语句；
- scope 始终注入；
- 安全测试证明用户输入不能直接注入标签、谓词或查询语句。

## 7. M5：验证快筛

### 交付物

- Assertion → Rule IR 的最小编译器；
- D1 SCC/资源流预筛；
- D2 one-hot/图可达性预筛；
- D3 区间传播；
- `not-modeled` 缺字段报告。

### 出口条件

- 三类检查各有正例、风险候选和未知例；
- 有环不自动报告死锁；
- 区间/结构结论明确标注其近似范围；
- Rule IR 每个节点有 source map；
- 缺单位、时间、概率或例外优先级时不产生伪 `proved`。

## 8. M6：有界 SMT 精化

### 交付物

- Z3 adapter（私有 context/worker）；
- D1 库存/动作/目标有界模型；
- D2 联合状态机有界模型；
- D3 Int/Real/BitVec 边界模型；
- witness 回放与多结果协议；
- 分层性能报告。

### 出口条件

- `sat` witness 能回放为动作/事件/资源或状态路径；
- 过近似假反例可标记为 spurious；
- 深度 `k` 的 UNSAT 只产生 `bounded-no-counterexample(k)`；
- solver timeout/resource exhaustion 产生 `unknown`；
- 每条 SMT assertion 能回到 claim 和原文 span；
- 无跨 worker context/AST 泄漏。

## 9. M7：版本与系统验收

### 交付物

- 版本快照、diff、supersedes；
- 资源价值/目标可达/旧存档连续三类兼容报告；
- 影响路径和需重跑列表；
- 端到端系统 fixture；
- CI、文档同步、安全、备份恢复演练报告。

### 出口条件

- 两个版本的断言变化可审计；
- 受影响的查询/验证任务被列出；
- 三类兼容性不被合并为一个布尔结论；
- 完成单游戏单子系统端到端链路；
- 所有强门槛通过：证据连续性 100%、domain/range 违规率 0、验证回映射 100%；
- 未达成的性能目标、未建模语义和已知风险有书面列表，不能以“基本可用”代替。

## 10. MVP 验收用例矩阵

| 用例 | 预期结果 | 覆盖 |
| --- | --- | --- |
| 明示“技能消耗 2 枚资源” | `COSTS` + quantity raw/value/unit + span | 抽取、证据、图谱 |
| 同名节点来自不同游戏 | 不自动合并，scope 隔离 | 命名空间 |
| 两来源给出相反数值 | 两个 Assertion 并存，需审核 | 冲突/生命周期 |
| 存在资源依赖环但有初始可执行序列 | 不报告死锁 | D1 假阳性边界 |
| LP 有净流但中间库存会负 | 反例或 not-modeled，不能报告可持续 | D1 |
| one-hot 合法但目标在 k 步不可达 | `bounded-no-counterexample` 或不可达报告，带 k | D2 |
| 多状态机共享锁竞争 | 联合转移暴露冲突 | D2 |
| BitVec 溢出而无界 Int 不越界 | 按运行时 BitVec 报告极值 | D3 |
| 周期只有“定期”无单位 | `not-modeled`，不换算 | 语义保守 |
| 查询要求未建模玩家体验 | `QUERY_OUT_OF_ONTOLOGY` | 路由拒绝 |
| solver 超时 | `unknown` + timeout 诊断 | 结果协议 |
| 版本改变配方 | diff、影响路径、兼容性分项报告 | 版本 |

## 11. MVP 不接受的替代说法

以下说法不能作为验收结论：

- “模型输出了合法 JSON，所以事实正确”；
- “图中有环，所以经济死锁”；
- “k 步内没有反例，所以全局安全”；
- “查询能执行，所以语义正确”；
- “有解，所以游戏可玩”；
- “平均延迟毫秒级，所以端到端 SLA 达成”；
- “多个 agent 都同意，所以可靠”。
