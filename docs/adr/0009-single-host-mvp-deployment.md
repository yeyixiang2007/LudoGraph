# ADR-0009：MVP 采用单机可复现组合部署

- **状态：** Proposed
- **决策域：** 部署与运维

## 背景

MVP 需要验证语义链路和可追溯性，而不是承诺大规模高并发。分布式部署会在早期引入队列、网络、租户、数据一致性和模型服务治理复杂度。

## 备选方案

1. 一开始采用多租户、跨区域、高可用微服务集群。
2. 采用单进程内存原型，不使用真实图存储和异步 worker。
3. 采用单租户/单机可复现组合：API/编排、图数据库、模型适配器、验证 worker，各通过适配器隔离。

## 决策

采用方案 3。MVP 本地或单机环境跑通真实合同链路；批量抽取、冷路径查询和验证可异步，所有任务有超时、幂等、审计和取消语义。

## 理由与边界

- 真实验证图投影、Assertion 历史和 solver worker 隔离；
- 易于固定硬件、版本和 fixture 进行复现；
- 不把“单机能跑”误写为高并发 SLA；
- 命名空间不是安全边界；
- 多租户、高可用和跨区域是后续部署设计。

## 推翻条件

- MVP 受明确交付约束必须满足多租户或高可用；
- 单机无法承载已测得的 fixture/solver 规模；
- 有成熟平台已提供等价的隔离、审计和可复现保障。

## 影响

需要容器/脚本化启动、版本锁定、备份恢复演练和 adapter 接口；未来横向扩展不能改变跨模块合同。
