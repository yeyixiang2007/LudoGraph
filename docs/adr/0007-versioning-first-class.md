# ADR-0007：把版本、冲突和修订作为一等语义

- **状态：** Proposed
- **决策域：** 数据治理与回归验证

## 背景

策划规则会修订、覆盖、分模式适用并产生来源冲突。把新值覆盖旧值会破坏审计，也无法说明旧验证结论是否仍然适用。

## 备选方案

1. 只保留当前最新事实。
2. 为每个游戏复制一个全量数据库，不保留断言级修订关系。
3. 保存不可变快照，Assertion 追加修订并以 `supersedes`/版本 diff/影响路径表达变化。

## 决策

采用方案 3。版本快照、来源修订、断言生命周期和验证结论均可追溯；MVP 提供 diff、三类兼容性报告和需重跑列表，不声称完整反例迁移。

## 理由与边界

- 支持冲突并存和历史审计；
- 可以识别受影响查询/验证任务；
- 把“资源价值不下降”“目标仍可达”“旧存档可继续”分开；
- 版本兼容关系尚未定义为单一精化定理；
- 自动迁移反例属于后续研究。

## 推翻条件

- 业务确认输入永不修订且无多来源冲突；
- 另一种事件溯源机制能够提供等价不可变断言和影响查询；
- 版本历史规模导致运行成本不可接受且留存政策明确允许归档/外置。

## 影响

所有接口必须记录版本四元组；导入不得覆盖；发布需 dry-run、影响分析和可回滚投影。
