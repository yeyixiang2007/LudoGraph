# ADR-0004：采用 Intent/槽位路由再进行方言编译

- **状态：** Proposed
- **决策域：** 自然语言图查询

## 背景

公开 Text2Cypher 结果显示，零样本端到端生成在不同模型和复杂度上差异很大；即使较高执行准确率也不能作为生产级可靠性证明。LudoGraph 还需要 scope、provenance、能力探测和多后端替换。

## 备选方案

1. 端到端 LLM 直接生成 Cypher。
2. 只支持固定模板，不接受自然语言扩展。
3. 采用 `Intent/slots → backend capability detection → Query IR → dialect compiler`。

## 决策

采用方案 3。Intent 是封闭枚举，编译器从白名单和参数生成方言查询；不支持的能力返回拒绝/降级。两步优于端到端是待通过 LudoGraph 工作负载实验验证的工程假设，不是已证明定理。

## 理由与边界

- 意图类别可枚举、可单测、可回归；
- 查询 IR 可跨后端复用，能力缺失可解释；
- 快速模板可满足低延迟场景；
- 复杂开放问题仍可能无法路由，宁可拒绝；
- 不对公开 benchmark 的数字做本项目准确率外推。

## 推翻条件

- 同一数据分布、同一硬件和安全约束下，端到端方案在准确率、可审计性、拒绝率和延迟上稳定优于分层方案；
- Intent 枚举造成不可接受的召回损失，并有可验证的开放 IR 替代；
- 系统长期只需固定查询模板。

## 影响

需要维护 Intent/Query IR、后端能力矩阵、编译器和拒答合同；用户输入必须参数化，不能直接注入 Cypher。
