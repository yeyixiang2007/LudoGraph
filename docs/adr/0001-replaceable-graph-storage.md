# ADR-0001：采用可替换的 LPG 图存储基线

- **状态：** Proposed
- **日期：** 设计草案阶段
- **决策域：** 图谱存储

## 背景

LudoGraph 的抽取合同需要保存有向谓词、关系限定值、来源证据、冲突与版本。属性图/LPG 与 Cypher 贴合这一访问形态，但公开资料不足以支持跨产品、跨硬件的性能排名；图数据库许可证与维护状态也会变化。

## 备选方案

1. Neo4j 作为直接、不可替换的系统依赖。
2. RDF/SPARQL store 作为唯一规范存储。
3. 嵌入式 Kùzu/LadybugDB 作为唯一运行时。
4. 可替换 Graph adapter，以 Neo4j 兼容 LPG/Cypher 作为首个 PoC。

## 决策

采用方案 4。抽取合同、Assertion 语义和查询/验证 IR 不依赖具体数据库；首个 PoC 可使用 Neo4j 兼容后端。直接边是可重建的物化投影，不是唯一历史来源。

## 理由与边界

- LPG 原生支持带属性的有向关系，适合当前 17 标签和 24 谓词；
- Cypher 生态可降低 MVP 的实现风险；
- 适配器边界允许迁移到 Apache AGE、FalkorDB、LadybugDB 或 RDF 投影；
- 不以公开 benchmark 推导 LudoGraph 的吞吐或 SLA；
- Kùzu 原项目归档等维护事实必须在选定版本时重新核验。

## 推翻条件

- 真实负载 PoC 显示首个后端不能满足数据一致性或可接受运维目标；
- 许可证/TCO 与交付方式不相容；
- 需求转为 OWL/RDF 推理且 LPG 无法保留所需语义；
- 已有稳定 PostgreSQL 运维且 AGE 在同一工作负载达标。

## 影响

需要定义后端能力矩阵、投影一致性测试和可迁移的索引抽象；具体 Cypher 只能出现在 adapter/compiler 层。
