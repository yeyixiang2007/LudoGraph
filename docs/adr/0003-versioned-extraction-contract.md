# ADR-0003：采用版本化、封闭的抽取 JSON 合同

- **状态：** Proposed
- **决策域：** 神经符号抽取接口

## 背景

抽取需要同时约束格式、本体和证据，但任何一层都不能替代事实审核。直接让模型生成图查询或数据库写入会把不可审计的模型输出变成系统事实。

## 备选方案

1. 模型直接生成 Cypher/数据库写操作。
2. 使用开放式三元组或自由 JSON，再由导入端猜测字段。
3. 只用 prompt 约束，不做确定性校验。
4. 采用版本化、封闭的 `nodes/claims/uncovered` JSON 合同，结构化生成后由确定性 validator 校验。

## 决策

采用方案 4。输出使用 17 个叶子标签、24 个谓词、显式限定值、四态 certainty、连续 evidence 和 uncovered；校验通过后才可进入导入。

## 理由与边界

- 合同可做离线 fixture、跨语言交换和版本兼容测试；
- `uncovered` 保留本体缺口，不把缺口伪装成无事实；
- 约束解码仅保证格式，validator 负责本体形状与证据边界；
- quote 连续性不等于自然语言蕴含，仍需人工/NLI 复核；
- 不做隐式单位、概率、身份或因果推断。

## 推翻条件

- 发现开放合同在真实语料上造成无法接受的本体召回损失，并能提出可验证的扩展机制；
- 新 schema 能在不牺牲证据和拒绝语义的前提下替代当前合同；
- 业务输入不再是规则文本，且确定性 span 证据不再适用（需另立合同）。

## 影响

模型 provider 必须适配同一合同；schema、validator、文档和 gold set 需要共同版本化。
